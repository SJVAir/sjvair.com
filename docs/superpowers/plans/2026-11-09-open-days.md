# Open Days Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- Every summary row says whether it can still change (`is_final`).
- New "open days" endpoints serve today's daily row "so far", and yesterday's until its nightly row exists, computed on request from hourly rows.

**Architecture:**
- `is_final` is computed in the two row serializers from the existing `is_settled` rule.
- A new module `camp/apps/summaries/open_days.py` picks the open days and builds unsaved `MonitorSummary` / `RegionSummary` instances from the stored hourly rows, so the existing serializers render them unchanged.
- Four thin endpoints (monitor, region, monitor bulk, region bulk) sit next to the daily lists.

**Tech Stack:** Django, django-resticus, Postgres.

**Spec:** `docs/superpowers/specs/2026-11-09-open-days-design.md` (it builds on
`docs/superpowers/specs/2026-11-09-scale-averaging-design.md`)

## Global Constraints

- Open days are today (Pacific), plus yesterday while
  `not is_settled('day', <yesterday's end>, now=now)` (the plain day margin, for every entry
  type) and only for series with no stored daily row for yesterday. There are at most 2.
- `is_final` on every row, at every resolution:
  `is_settled(resolution, period_end(resolution, row.timestamp), now=now, late=<switch type>, peak_8h=<daily_statistic == 'max_8h'>)`.
  Open rows are therefore always `false`.
- Today's figures use the "so far" rules:
  - `mean_24h`: the mean of the hourly means so far.
  - `max_1h`: the highest hourly mean so far.
  - `max_8h`: the highest window starting today with at least 6 of its 8 hours.
  - The 75% rule and the standard exception don't apply.
- An earlier open day uses the strict functions already in `peaks.py`.
- "Has data" for the figures: a complete monitor hour, or any region hour. Hourly means
  `<= SENTINEL_MAX` (-900) are skipped. The row's other stats roll up every existing hourly
  row (`rollup_summaries`, or `rollup_region_stats` plus `station_count` = the max across
  hours).
- Only the field `daily_statistic` names is set; the other figure fields are `null`. Entry types
  with no `daily_statistic` get all three `null`.
- Caching: `private, max-age=60`, an ETag, `If-None-Match` → 304; errors `no-cache`.
- Bulk open endpoints are paginated by owner, 100 owners per page. Single-owner endpoints aren't
  paginated.
- Pacific date math only through `camp/apps/summaries/periods.py`.
- Tests use `django.test.TestCase` with pytest-style `assert`.
- No Claude or AI attribution in commits.
- Pass monitor ids to commands as `--monitor=<id>`, since sqids can start with `-`.
- Test command, run from the worktree root. Never print `$DBURL`:
  ```bash
  DBURL=$(grep ^DATABASE_URL .env.test | cut -d= -f2- | sed 's#/sjvair$#/sjvair_open_days#')
  podman run --rm --network sjvaircom_sjvair-net --env-file .env.test -e BAM_MIRROR_ENABLED=0 \
    -e TWILIO_AUTH_TOKEN=test-token -e DATABASE_URL="$DBURL" -v "$PWD":/app:z -w /app \
    sjvair-com-test:latest pytest <paths> -q
  ```
  Full suite: replace `<paths> -q` with `-n 4 --dist loadscope`.

## Review Focus

1. **Just after midnight with yesterday's row already stored** (the rollup ran at 01:00). The
   open endpoint must not also serve a computed yesterday. Pinned in Task 2
   (`test_stored_yesterday_not_open`).
2. **A monitor with several processors** (AQLite raw and aggregated). The single-owner endpoint
   honours `?processor=`, and bulk honours the published-series default. Pinned in Tasks 3
   and 4.
3. **Today with only incomplete hours.** The stats roll up, but the figures are `null`. Pinned
   in Task 2 (`test_today_incomplete_hours`).
4. **DST days.** Today's hour list and yesterday's settle time on fall-back and spring-forward
   days. Pinned in Task 2 (`test_open_days_dst`).
5. **A bulk request with no scope** stays bounded: one page, 100 owners, bounded queries.
   Pinned in Task 4 (`test_bulk_open_query_count`).

### Task 2: Open-day rows

**Files:**
- Create: `camp/apps/summaries/open_days.py`
- Modify: `camp/apps/summaries/peaks.py` (add so-far figure functions)
- Test: `camp/apps/summaries/test_open_days.py` (create)

**Interfaces:**
- Consumes: `day_hours`, `max_1h`, `max_8h`, `mean_24h`, `peak_entry_models`, `standard_for`, `SENTINEL_MAX` from `peaks.py`; `rollup_summaries` and `rollup_region_stats` from `aggregators.py`; `is_settled`; and `period_start` / `period_end` / `iter_hours`.
- Produces:
  - In `peaks.py`: `SO_FAR_FUNCTIONS = {'max_1h': ..., 'max_8h': ..., 'mean_24h': ...}`, each `(day_hours, hourly) -> float | None`. They take no gate. `max_8h` keeps the 6-of-8 window rule and only counts windows starting in `day_hours`. Each returns `None` when there's no data.
  - `open_days(now: datetime) -> list[datetime]`: Pacific day starts, today last.
  - `build_open_rows(kind: str, owner_ids: list, entry_model, now: datetime, processor_q: Q | None = None) -> dict[owner_id, list[MonitorSummary | RegionSummary]]`.
    - The rows are unsaved model instances with `resolution='day'` and `timestamp` set to the day start, plus all stats fields and the figure fields.
    - For monitors, `processor_q` filters the hourly rows' series; `None` means all processors.
    - Yesterday is included per series only when that series has no stored daily row for it.
    - It runs one hourly query and one stored-daily-existence query for all of `owner_ids`.

- [ ] **Step 1: Write failing tests** (monitors and regions with hand-made hourly rows):
  - `test_open_days_window`: at 00:30 Pacific, `open_days` is [yesterday, today]; at 03:00, only [today].
  - `test_open_days_dst`: on 2026-11-02 at 02:30, yesterday (25 h) is still open; on 2026-03-09 at 02:30, yesterday (23 h) is open, and today's `day_hours` has 24 hours.
  - `test_today_so_far_figures`: with 3 complete O3 hours (40, 90, 60), `max_1h` is 90.0. With PM25 hours 10 and 20, `mean_24h` is 15.0. CO with 5 hours gives `max_8h` None; with 6 hours, their mean.
  - `test_today_incomplete_hours`: with only incomplete hours, `count`/`mean` are set and `max_1h` is None.
  - `test_sentinel_skipped_so_far`: a -999 hour is ignored by the figure.
  - `test_yesterday_strict`: at 00:30 with 17 complete O3 hours yesterday, `max_1h` is None (strict).
  - `test_stored_yesterday_not_open`: once a stored daily row exists for yesterday, only today's row is built for that series.
  - `test_region_rows`: `station_count` is the max across hours, and there's no `is_complete` attribute use.
  - `test_processor_q`: AQLite rows `''` and `AQLiteHourlyAggregator` give 2 rows per day without a filter, and 1 with `Q(processor='AQLiteHourlyAggregator')`.
  - `test_no_figure_type`: temperature rows have all three figures None.
  - `test_query_count`: `build_open_rows` for 5 monitors runs at most 2 queries.
- [ ] **Step 2: Run** `camp/apps/summaries/test_open_days.py`. Expected: FAIL.
- [ ] **Step 3: Implement.**
  - Read the hourly rows over `[open_days[0], end of today + 7 h)` with every stats column the rollups need, plus `mean`, `is_complete` (monitors) and `weight`/`station_count` (regions).
  - Group them by `(owner, entry_type, processor)` for monitors and `(owner, entry_type)` for regions.
  - Each row's stats come only from its own day's hours. The figure input is complete and non-sentinel means, and may include the 7 h tail for an earlier day's `max_8h`.
- [ ] **Step 4: Run.** Expected: PASS.
- [ ] **Step 5: Commit** `Summaries: build open-day rows`.
